# 深度优化性能与可靠性报告

日期：2026-10-02。保留本地优先架构与现有模型配置；优化针对可复现的调度、传输与加载问题。

## 批量任务调度

原实现先给所有文档创建 `asyncio.Task`，再让它们等待信号量。并发限制了同时执行的模型调用，却没有限制任务的分配数。新实现采用滑动窗口，只保留并发上限数量的文档任务，按完成顺序产出结果，调用方离开时取消剩余任务。

实测条件：10,000 个模拟文档、并发 3；文档操作被事件挂起，以测量任务进入运行态前后的 Python 分配。两个路径依次在同一进程中运行。

| 指标 | 旧调度逻辑 | 当前实现 |
| --- | ---: | ---: |
| 在途文档任务 | 10,000 | 3 |
| 调度时间 | 173.320 ms | 4.814 ms |
| Python 峰值分配 | 15,187,526 B | 8,164 B |

[原始 JSON](benchmarks/scheduler.json)。这些数字来自一次本机模拟，时间会受机器负载影响；不包括文档列表自身、模型推理、解析、向量化、磁盘 I/O 或全应用内存，不能换算成「摄取总耗时加速」。任务数量从 O(文档数) 降为 O(并发数) 是实现所保证的性质。

复核：

```bash
uv run python scripts/benchmark_scheduler.py --documents 10000 --concurrency 3
```

## 常用页面的延迟加载

对比同一工作区的生产构建输出，单位为未压缩 JavaScript KB。

| 模块 | 前一轮 | 当前 |
| --- | ---: | ---: |
| 记忆页 | 248.26 | 92.78 |
| 专家评测页 | 125.10 | 72.79 |
| 图谱渲染（打开图谱才加载） | 含在记忆页 | 157.67 |
| 测验管理（打开测验标签才加载） | 含在专家页 | 19.14 |
| 检索配置对比（打开面板才加载） | 含在专家页 | 35.73 |
| 主入口 | 605.45 | 612.94 |

延迟加载减少只使用卡片、只查看专家度时要加载的模块；所有功能都打开时，总下载量不会按这个比例减少。主入口增加约 7.5 KB，对应新的流协议解析与订阅韧性等公共逻辑。Mermaid、PDF 和部分语法高亮资源仍较大，继续保留构建告警。

图谱数据请求也改为打开标签后才发出，最近结果缓存 30 秒；卸载图谱标签时取消无用请求。浏览器资源记录验证了图谱、测验和对比面板在对应操作之前未加载、操作后正常加载。

## 修复的可靠性缺陷

- SSE 队列满时为塞入结束哨兵而丢掉最旧事件，导致慢客户端缺字 / 缺引用：改为独立判断生产者完成并排空队列，回归测试用容量 2 的队列与慢消费者验证逐帧完整。
- 同会话登记覆盖旧任务却不取消它：当前取消旧任务并等待清理，再开始下一轮；删除与退出也等生成结束后才释放资源。
- 排队数量混用全局等待量，且未运行的协程取消后遗留：当前按空间记账并由完成回调确定清理；超时不能抹掉任务后继续关库。
- 前端只识别 `\n\n`，CRLF 流无法正确分帧，且 reader 没有确定释放：现在支持多种换行、UTF-8 跨包和多行 data，取消 / 错误时确定关闭 reader，未结束的大帧受 1,048,576 个 UTF-16 代码单元上限保护。
- 进度订阅断开后不再恢复，回调对象变化又会频繁重连：当前仅 GET 自动退避重连，POST 不重放，永久 4xx 停止重连，连接回调读取最新引用。
- 命令面板缺少 cmdk 根容器：已修复并补充真实 DOM 回归；语义命中可以不含查询字面文本且仍可见，点击直接打开来源。
