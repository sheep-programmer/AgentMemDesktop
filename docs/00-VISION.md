# AgentMem · 产品愿景与核心概念

> 一个本地优先的 AI 知识库，能通过持续学习与反馈迭代，成长为某个垂直领域的专家。

---

## 1. 一句话定位

AgentMem 不是又一个 RAG 聊天框。

普通 RAG：`提问 → 检索文档 → 拼进 Prompt → 回答`。知识库是静态的，喂多少文档就是多少能力，用一年和用一天没区别。

AgentMem：在 RAG 之上叠加经验沉淀与可验证的进化闭环，让系统在使用过程中不断积累"方法论"和"踩坑记录"，并用领域测验集量化验证这些经验是否真的带来提升。

> 用得越久 → 越懂你的领域 → 专家度指数可量化上涨。

---

## 2. 五层记忆架构

这是 AgentMem 的骨架。每一层都是上一层的抽象与提炼。

| 层 | 名称 | 内容 | 产生方式 | 生命周期 |
|---|---|---|---|---|
| L0 | 原始层 Corpus | 原始文件、网页、对话记录、代码 | 用户投喂 / 抓取 | 永久，只增不改 |
| L1 | 语义层 Chunks | 切片 + 向量 + 全文索引 | 自动解析切分 | 随 L0 重建 |
| L2 | 知识层 Knowledge | 知识卡片（概念/事实/流程）、实体关系图 | LLM 抽取 + 人工校订 | 可编辑、可版本化 |
| L3 | 经验层 Insights | 启发式经验条目："遇到 X 场景，应当 Y，因为 Z" | 从交互反馈中蒸馏 | 有置信度，可升降级、可淘汰 |
| L4 | 人格层 Persona | 领域专家画像：术语表、方法论、输出风格、质量标准 | L2/L3 聚合 + 用户设定 | 长期演化 |

回答一个问题时的上下文装配顺序：
```
L4 Persona（我是谁，怎么说话，什么算好答案）
  + L3 Insights（这类问题的已知经验与坑）
  + L2 Knowledge（相关概念卡片与实体关系）
  + L1 Chunks（原文证据，带引用）
  → LLM → 带引用的回答
```

## 3. 进化闭环 Evolution Loop

系统的"学习"发生在这个循环里，而不是靠微调模型。

```
┌──────────────────────────────────────────────────────────┐
│                                                          │
│  ① Interact    用户提问，Agent 基于 L1~L4 作答            │
│       ↓                                                  │
│  ② Trace       完整记录轨迹：问题 / 命中的证据 /          │
│                 用到的 Insight / 回答 / 工具调用           │
│       ↓                                                  │
│  ③ Critique    评价这次回答                              │
│                 · 显式：用户 👍 / 👎 / 直接纠错            │
│                 · 隐式：用户是否追问、是否复制了答案        │
│                 · 自动：LLM-as-Judge 按 Persona 标准打分   │
│       ↓                                                  │
│  ④ Distill     从"差评 + 纠错 + 好评"中蒸馏候选经验       │
│                 产出 InsightCandidate（待定，置信度 0.3）  │
│       ↓                                                  │
│  ⑤ Consolidate 去重 / 合并 / 冲突消解                     │
│                 与现有 L3 矛盾的 → 标记冲突待裁决          │
│       ↓                                                  │
│  ⑥ Evaluate    用领域测验集（EvalSet）跑 A/B：            │
│                 注入新经验 vs 不注入，分数是否提升？        │
│       ↓                                                  │
│  ⑦ Promote     通过 → 置信度↑，进入默认注入池             │
│                 未通过 → 置信度↓，低于阈值则归档淘汰        │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

关键设计原则：经验必须可证伪。 任何一条 Insight 都要能被 EvalSet 验证，否则系统会退化成"越用越多噪音"。这是 AgentMem 区别于普通 memory 库的核心。

## 4. 专家度指数 Expertise Index

把"这个 AI 在这个领域有多专业"变成可视化的数字。五个维度（0–100）：

| 维度 | 含义 | 计算方式 |
|---|---|---|
| 覆盖度 Coverage | 领域知识图谱的填充率 | 已有知识卡片 / 领域大纲节点数 |
| 准确率 Accuracy | EvalSet 上的得分 | 最近一次全量评测正确率 |
| 一致性 Consistency | 同一问题多次提问答案是否稳定 | 重复提问的语义相似度 |
| 引用率 Groundedness | 回答中有原文支撑的比例 | 带有效引用的句子 / 总句子 |
| 经验密度 Insight Density | 高置信度经验条目数量 | 置信度 > 0.7 的 Insight 数 |

前端以雷达图 + 时间成长曲线呈现——这是产品最有说服力的一屏。

## 5. 核心约束（贯穿全部设计）

1. 本地优先：默认全部数据落在本地磁盘，不联网也能用（配合 Ollama 本地模型）。
2. 模型完全可插拔：LLM / Embedding / Reranker 三类各自独立配置，支持本地与第三方 API 混用（例：本地 Embedding + 云端 LLM）。换模型不改一行业务代码。
3. 多知识库隔离：一个安装可以有多个 Space（如"Android 逆向""医药研发"），各自独立的 L0–L4 与专家画像。
4. 一切可追溯：每个回答都能下钻到它引用的原文片段与经验条目。
5. License 干净：自研核心 + 依赖库均选择宽松协议（MIT / Apache-2.0），避免 AGPL 传染。

## 6. 目标用户与典型场景

| 场景 | 说明 |
|---|---|
| 逆向工程师 | 投喂 APK 分析笔记、协议文档，沉淀"这类壳怎么脱""这种混淆怎么认" |
| 研究者 | 投喂论文库，沉淀"这个方向的主流方法与各自缺陷" |
| 律师 / 合规 | 投喂法条与判例，沉淀"这类条款的常见争议点" |
| 个人第二大脑 | 投喂笔记与收藏，成为"最懂我的助理" |

---

## 7. 不做什么（反向边界）

- ❌ 不做多租户 SaaS / 用户体系（本地单人使用，v1 不做登录）
- ❌ 不做模型微调 / LoRA 训练（进化靠上下文工程，不靠改权重）
- ❌ 不做通用 Agent 工作流编排平台（不与 Dify / n8n 竞争）
- ❌ 不做移动端
