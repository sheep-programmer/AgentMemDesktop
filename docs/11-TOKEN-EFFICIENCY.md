# 上下文 token 优化与方法对照

日期：2026-10-02。目标是在保留现有检索候选、来源定位与用户指令的基础上，减少发送给回答模型的重复和辅助内容。

## 参考了哪些方法

| 方法与一手资料 | 思路 | 本项目的取舍 |
| --- | --- | --- |
| [LangChain Contextual Compression](https://www.langchain.com/blog/improving-document-retrieval-with-contextual-compression) | 在检索后按问题抽取内容或过滤文档；可使用模型抽取器、嵌入过滤器与处理管线 | 采用检索后处理的思路，使用本地词面匹配与原文句子窗口，避免新增逐文档模型调用 |
| [LlamaIndex Sentence Embedding Optimizer](https://developers.llamaindex.ai/python/examples/node_postprocessor/optimizerdemo/) | 按句子与问题的嵌入相似度筛选，减少回答输入 | 借鉴句子筛选与对照计量；当前使用保守词面信号，不引入额外句子嵌入调用 |
| [Dify Parent-child Retrieval](https://dify.ai/blog/introducing-parent-child-retrieval-for-enhanced-knowledge) | 小切片匹配，再提供较完整父段，兼顾精度与上下文 | 项目已有相邻切片合并。父段扩展会增加输入量，因此本轮在合并之后处理冗余，而非扩大索引层次 |
| [LongLLMLingua，ACL 2024](https://aclanthology.org/2024.acl-long.91/) | 面向长上下文的任务相关提示词压缩，论文报告了其基准上的成本与质量收益 | 不直接套用论文压缩率；这类模型压缩需要额外运行依赖与独立质量评估，本轮先实现无模型的可对照策略 |

这些参考并不表示本项目实现了同名框架组件或获得了其基准效果。当前压缩是确定性的原文摘取，不是语义摘要模型。

## 已实现的策略

聊天输入栏新增「上下文：标准 / 节省」。菜单使用两张独立选项卡片，包含图标、边框、用途说明与当前选中标记，支持键盘单选。默认标准模式，输入估算通过 `context` SSE 事件展示；可在下一次提问前切换，也适用于重新生成和起手问题的统一发送入口。

| 层 | 标准模式的估算预算 | 节省模式的估算预算 | 处理方式 |
| --- | ---: | ---: | --- |
| L1 原文证据（含来源标签） | 2,000 | 1,200 | 标准沿用原有预算；节省可先摘取相关句子及前后句，再分配预算 |
| 历史消息 | 2,400 | 1,200 | 保留连续的最近完整问答；最近一轮原样保留，故对该轮是软上限 |
| L2 知识卡片 | 1,200 | 500 | 保留能放入的完整卡片条目，仍沿用单张卡片既有正文上限 |
| L3 经验 | 1,200 | 600 | 按置信度选择；适用条件与做法完整保留，可省略解释依据，放不下的规则整条跳过 |

L4 人格、固定引用规则和当前问题保持完整，system 不随模式变化。预算是启发式 token 估算，不保证适用于每家提供方的分词器，也不是整个模型上下文窗口的硬上限。尤其最近一轮很长时仍可能超过历史预算，既有上下文溢出恢复会继续生效。

历史最多仍取最近八条 user / assistant 消息，通常为四轮问答。保留的内容不改写，数据库中的原始会话不裁剪。窗口淘汰会改变前缀；实际缓存收益与费用应结合提供方 usage 记录评估，不能仅按裁掉的字符推算账单。

### 原文窗口的保护

- 只在较长且可按句子处理的正文中选择窗口，保持原顺序、完整数字与单位，并明确标出省略位置。
- 保留命中句的前后句，以及正文首尾。被省略的中间内容没有被重新编写成事实。
- 单个中文双字命中信号过弱时不摘取；混合问题中的英文词必须实际命中，才可作为强信号。
- 分散出现的查询词无法被选定窗口覆盖时，回退到原预算策略。
- 宽泛概述、比较、趋势和范围类问题跳过句子摘取；代码、Markdown 表格和列表同样跳过摘取，仍受既有证据预算限制。
- 索取原文时，检索管线自动使用标准预算。标准策略仍存在证据长度上限，不代表整份文档必然全部发送。

这些保护减少明显的误裁风险，无法证明所有同义表达、否定关系和跨段依赖都保留。聚焦事实查询适合尝试节省模式；复杂分析可以切回标准模式对照。

### 记录与引用一致性

装配返回实际保留的证据 marker、经验 ID 和卡片 ID。流中的经验、轨迹的 `used_insights` / `used_cards` 和经验使用计数采用同一份清单。预算丢弃的编号不会注册为可用引用，避免模型沿用历史编号引用本轮没收到的内容。原始切片 ID、内容和定位信息保留，引用仍可打开来源。

估算通过流即时展示，当前不单独存入轨迹。费用统计继续采用模型提供方返回的实际 usage。演示模式不伪造节省数值。

## 离线对照

使用五个明确标识的合成场景，对比此前装配策略、标准模式和节省模式。每个场景装配 20 次；没有模型、摘要或嵌入 API 调用。两套本地 `tiktoken` 编码器统计消息正文 token，不含聊天协议开销，不等于所有提供方的账单 token。

| 合成场景 | 原策略 / o200k_base | 标准 / o200k_base | 节省 / o200k_base | 节省模式减少 | cl100k_base 的减少 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 短事实问答 | 446 | 446 | 446 | 0% | 0% |
| 长正文中间的事实 | 1,981 | 1,981 | 541 | 72.7% | 74.7% |
| 较长的四轮历史 | 2,860 | 2,257 | 1,051 | 63.3% | 64.3% |
| 较长历史、卡片与经验 | 8,734 | 4,180 | 1,919 | 78.0% | 78.9% |
| 短表格与代码 | 440 | 440 | 440 | 0% | 0% |

短内容保持相同输入，避免无意义的改写。长正文样例中，原来的头尾裁剪漏掉了中间的测试数值及限制条件，节省窗口保留了这两个指定片段。其他样例的指定数值、单位、限制条件和最近用户要求也全部保留。

这是片段保留检查与输入量测量；没有用真实回答模型评估语义正确率、完整率、真实知识库问题分布、延迟或最终账单。合成材料中的试验数字仅用于测试，不是医学资料。保留几个指定片段也不能代表完整语义无损。

装配耗时与编码器版本、输入层数和机器负载有关，详见 [原始 JSON](benchmarks/context-tokens.json)。新增原文筛选及对照计量有本地 CPU 成本；本轮没有宣称端到端响应加速。

```bash
uv run python scripts/benchmark_context.py --output docs/benchmarks/context-tokens.json
```

## 真实链路的省 token 与提速（2026-10-04）

上面的对照只用合成材料、不调模型。这一轮直接对真实后端提问：测试使用远端回答服务，以及本机向量化与重排服务（MPS），测试空间共 7 篇文档，标准上下文模式。脚本见 `scripts/benchmark_chat.py`，原始数据见 [chat-latency.json](benchmarks/chat-latency.json)。

### 先看浪费在哪

- 不相关的证据占满名额。问「长江大学哪一年建立的」，8 条证据里 6 条重排分是 0.000（EGFR 表格行、英文长段落），吃掉证据预算的九成。检索按名次截 top-8，没有任何相关性门槛。
- 短文档的概要与正文重复。同一篇短文档的概要切片（摄取时由模型写成，没有原文区间）和正文切片一起进上下文，回答于是同一事实挂两处引用（[1] 概要、[3] 正文），概要那处点开定位不到原文。
- 卡片重复证据、彼此重复、或者答非所问。39 个问题里一半以上的注入卡片与同轮证据重合 0.85 以上；「关键判定阈值」被抽成两张标题略异的卡片；问长江大学时另外三张是 EGFR 结构设计卡片（相似度 0.39，最相关那张 0.66）。
- 推理模型的「先想再答」。测试回答服务默认带推理：一次「把追问改写成独立问题」先吐 75–90 个推理 token，单次 5 秒上下。
- 最慢的一步是本地重排：40 条候选约 5–9 秒（波动随机器负载），占检索耗时的九成以上；而「重新生成」与评测 A/B 两臂会把同一问题、同一批候选再打一遍分。

### 改了什么

| 改动 | 位置 | 说明 |
| --- | --- | --- |
| 相对相关性下限 | `retrieve/relevance.py`，`RetrievalSettings.relevance_floor`（默认 0.1） | 重排分低于本轮最高分 10% 的证据不送给回答模型。只在分数是 0–1 概率且最高分 ≥ 0.5 时生效：宽泛的概览题（「这些文档讲了什么」最高 0.007）一条不裁。只作用于问答链路，`/search` 调试接口仍返回完整 top-N |
| 概要去重 | 同上 | 一篇短文档（正文合计 ≤ 1000 token）的正文切片全部在场时丢掉它的概要切片，引用落在可高亮的原文上；缺一条正文就不丢 |
| 卡片去重与相关性 | `prompts/answer.py`、`retrieve/pipeline.py` | 正文 90% 以上已出现在本轮渲染出的证据（或先入选卡片）里的卡片不再重复；被预算截掉的部分只留在卡片里时照送。与最相似卡片相差 0.2 以上的卡片不召回 |
| 改写不推理 | `retrieve/rewriting.py`、`providers/adapters/openai_compatible.py` | 指代补全 / 扩展 / HyDE 显式要 `reasoning_effort: none`；服务端不认这个参数（400/422 且点名 reasoning）时去掉重来并记住，不影响可用性。只有 OpenAI 兼容适配器接收这个提示 |
| 正式回答的推理强度可配 | provider `extra.reasoning_effort` | 默认不改变正式回答的行为；需要更快首字时在「设置 → 模型」该 provider 的 extra 里写 `reasoning_effort: none`（取值以提供方为准）。代价见下 |
| 问题向量与重排分缓存 | `providers/registry.py` | 按（provider、模型、问题、候选正文摘要）逐条缓存，挂在注册表上，模型配置一变随注册表整体作废。文档向量不缓存。全部命中时不记用量 |

### 实测（中位数）

改动前 3 轮；改动后每轮先重启后端（缓存为空）共 3 轮；「再问一遍」是缓存命中后同一批问题再问 2 轮，模拟「重新生成」（其中一次追问遇到提供方 429 限流，已剔除）。

| 场景 | 输入 token 前 → 后 | 证据条数 | 检索完成 ms 前 → 后（冷） | 首字 ms 前 → 后（冷） | 总耗时 ms 前 → 后（冷） | 再问一遍：检索 / 首字 / 总耗时 ms | 模型调用 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 短事实「长江大学哪一年建立的」 | 3,409 → 1,284 | 8 → 1 | 9,562 → 5,640 | 12,259 → 10,523 | 13,178 → 11,310 | 32 / 1,574 / 1,838 | 1 |
| 表格参数「CMPD-005 生物利用度和半衰期」 | 4,189 → 4,189 | 8 → 8 | 8,095 → 7,248 | 12,682 → 10,882 | 13,483 → 11,205 | 49 / 2,423 / 2,824 | 1 |
| 同会话追问「那它…降解多少」 | 5,316 → 5,161 | 8 → 7 | 11,026 → 9,866 | 14,714 → 12,151 | 15,746 → 12,977 | 7,785 / 10,433 / 10,950 | 2 |
| 要点解释「KRAS 首选哪种弹头」 | 3,393 → 1,873 | 7 → 3 | 6,006 → 6,981 | 13,392 → 9,753 | 13,407 → 11,267 | 34 / 4,620 / 5,817 | 1 |
| 跨文档「CMPD-003 晶型和熔点」 | 4,264 → 4,264 | 8 → 7 | 4,154 → 6,624 | 7,302 → 8,662 | 7,489 → 9,280 | 44 / 4,192 / 4,426 | 1 |
| 长文段落「为何共价弹头克服不了 C797S」 | 3,476 → 2,103 | 7 → 2 | 9,048 → 9,085 | 13,759 → 12,565 | 15,607 → 14,486 | 40 / 4,243 / 7,510 | 1 |
| 全部 18 轮 | 平均 3,992 → 3,134（−21%） | | 7,236 → 7,358 | 12,990 → 10,531 | 13,445 → 11,289 | 34 / 3,226 / 3,455 | |

输入 token 是提供方 usage 返回的 `prompt_tokens`。追问那一轮的改写调用：耗时中位数 5,176 → 1,949 ms，产出 113–133 → 42–45 token（含推理 token）；改写结果前后都是正确补全了指代的同一问题（措辞在几种近似说法间变化，改动前同样如此）。前后各 18 轮回答都包含预期事实（`facts_ok` 18/18）。各有 1 轮没有被识别的引用：改动前是一次追问没写引用，改动后是一次短事实把 `[^c1]` 写成了 `[^1]`；其余轮次的引用都落在本轮实际收到的证据编号上，短事实题不再同时引用概要与正文。

怎么读这张表：

- 省 token 是确定的：聚焦问题省 40%–62%；证据本来就都相关的表格题（同表多行）不变，这是有意的——相对下限不动「都相关」的情形。离线对同一批 39 个问题（含黄金评测集 29 题）回放，上下文估算合计减少 13%，评测集里能逐字核对的要点没有一条因裁剪而从上下文中消失。
- 冷启动的检索耗时没有变快：重排候选数没动（见下面「没做的」），5–9 秒的波动来自本机负载，前后差异在噪声内。冷启动的首字与总耗时略有下降，主要来自输入变短与追问的改写提速，但样本量小、云端波动大，不宜当作确定的提速。
- 「重新生成」/ 重复提问的检索从 5–10 秒降到 30–50 ms，总耗时只剩回答模型本身。评测的 A/B 两臂同理。

### 正式回答关掉推理的取舍（未默认开启）

用同一批上下文直接调用提供方，各 1 次：默认推理时首字 1.8–5.7 s（中位 3.4 s）、产出 162–546 token（其中推理 94–269）；`reasoning_effort: none` 时首字 0.6–5.7 s（中位 0.9 s）、产出 19–142 token。5 题事实都对、都带引用，但回答明显更短，「先结论、再依据、再注意事项」的结构与 quality_bar 要求的适用范围说明更常被省略。这属于答案详略的产品取舍，5 道题也证明不了复杂分析题不受影响，所以只做成可配置项，默认行为不变。

### 试过但没做的

- 缩小重排候选池：此前已实测会漏证据（黄金评测集上下文召回 1.0 → 0.875），本轮不动。重排截断到 512 token、改批大小、换 bf16 / fp32 / CPU，在本机都没有稳定收益（7.3–13 s 区间内来回），没有采用。
- 绝对分数阈值：「这些文档讲了什么」整轮最高 0.007，绝对阈值会清空真正相关的概要切片。
- 提高前缀缓存命中：system 在同一 Space 内已逐字节稳定，provider 实测只回报 256 个缓存 token（同会话追问有一次命中 5,120），没有找到可控的改进点。
- 经验（L3）总被注入：本 Space 的经验没有写进向量索引，召回走「按置信度兜底」，每题都带同样两条（约 350 token）。这是索引数据问题，不在本轮改动范围。
- 概要与卡片中的「原文没有的内容」：长江大学的概要和由它抽出的卡片都写了正文没有的校址与前身院校。去掉重复概要后，回答仍会从卡片里引述这些内容。根因在摄取时的概要生成，未处理。
