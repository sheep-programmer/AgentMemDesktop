### 已知技术债（记录在案，非阻塞）

| 项 | 影响 | 修法 | 优先级 |
|---|---|---|---|
| 经验晋升/淘汰的判定阈值远低于噪声 | 已解决（触及核心承诺，且经历过一次自我更正）：`MIN_EVAL_DELTA = 1.0`，A/B 分差绝对值 ≥ 1 就升降一批经验的置信度。量化证据：三次同配置的 A/A，旧阈值下 3 次全部被判为「有显著差异」——假阳性率 100%，经验的晋升与淘汰基本由噪声驱动，而 README 承诺的是「用测验集证明提升」。现改为按 2 倍标准误随题量缩放：`2 × 16 / √N`（8 题→11.3、29 题→5.9、50 题→4.5；常量来自完整链路下的干净 A/A 样本（见 `expert/noise.py`）），三次 A/A 的配对总分差（−2.67 / +6.0 / −7.25）全部被正确判为无差异。⚠️ 第一次修正时定错了常量：当时测到的 A/A 逐题差值是 `[-8,+94,-25,+25,0,+3,+97,+3]`，据此把噪声定为 32、8 题阈值 22.6，并得出「评测集需要几十题」的结论——但那批数据被下一条的「假零分」严重污染，修掉后逐题差值标准差只有 14.9。按 32 定阈值会让进化闭环拒绝晋升真正有用的经验，矫枉过正。常量已移到 `expert/noise.py`，注释里保留了这段来龙去脉 | 8 题能分辨约 10 分的差异，比先前估计的乐观得多；题量加到 20 题可到约 7 分 | 已关闭 |
| 评测里还有三条「假零分」路径 | 已解决（前一次只堵了 `ValueError` 那一条）：① 裁判漏写汇总字段 `score` 时 `data.get("score", 0.0)` 默认成 0 并算作测得——复现：「四维全 1.0、verdict『全对』」被记成零分；现按提示词自己的定义（四维加权和，权重抽成 `JUDGE_WEIGHTS` 单一来源并有防漂移测试）算回。② 单题抛异常（限流、超时）记 0 分且 `measured` 默认 True——连锁后果：「带经验」那轮撞上限流时每题 0 分，delta = −基准分，远超阈值，把所有候选经验一起降级；现记为未测得，且进化闭环在配对有效题数不足一半时跳过判决、面板写明原因。③ 多臂对比的逐题差值不看 `measured`，一边占位 0 分、一边 97 分就凭空出 +97；现只在两臂都测得的题上配对，总分差也按共同题集重算（进化闭环同改）。另：整段 JSON 因评语里的 ASCII 引号而非法时，分数其实完整写在开头——两次 A/A 里 32 次评分有 5 次因此作废，现从原文抽回数值字段（真实 0 分照常计入，越界值不可信）。实测修复后 A/A 有效配对题数从 6、7 题回到 8/8 | — | 已关闭 |
| 留一法归因的噪声底与贡献值口径有误 | 已解决：`noise_floor` 取单次 A/A 的总分差——一个样本碰巧很小时会让噪声冒充信号；`contribution` 用两臂原始总分相减（不配对）；`items_helped/hurt` 逐题比原始分数，「去掉该经验」那臂某题撞限流（占位 0 分）会被算成「这条经验帮了这道题」。现一律复用 `compare()` 的配对差值，噪声底取实测 A/A 与按题量标定的理论阈值中的较大者 | — | 已关闭 |
| 检索旋钮的调优结论需要重测 | 已完成：评测集由 8 题扩到 29 题（`/evals/generate` 针对 4 篇实质文档出题，逐题核对过参考答案），一次 8 臂对比、同一批题目配对 t 检验，A/A 对照臂 t = 0.00 自检通过、逐题差值标准差 13.2 与标定一致。结论：图谱扩展 / 关多样性 / 证据 12 条 / 证据 5 条 / HyDE / 关 AutoMerge 六个旋钮，\|t\| 全部 < 1，对回答质量都没有可测出的影响（标准误约 2–3 分，真实效应基本在 ±5 分以内）。据此不改任何默认配置。成本上各臂提示词 token 差异 ≤ 11%，延迟被服务商波动淹没，也不构成改动理由。证据预算 bug 修复后对「证据 12 条 / 5 条」的两次重跑作废：那两轮跑的时候本机的 sentence-transformers 已被误删（见「本地 CI 模拟卸掉了可选依赖」一条），全程没有向量检索和重排，测的不是真实系统。已在完整链路上重跑（29/29 题配对、无重试无失败）：证据 12 条 t=−0.55、证据 5 条 t=−1.75，均不显著。注意证据 5 条若只用本轮实测标准差会得到 t=−2.08——这一轮 A/A 恰好很安静（逐题标准差 9.7），标定下限正是防这种情况的；且上一轮它是 +1.28，方向相反。结论不变：默认 8 条 | — | 已关闭 |
