# 摄取与维护的数据一致性改进

日期：2026-10-02。主要修复同一应用进程内，摄取、重新解析、聊天、重建、删除和导出之间的操作竞态。

## 问题与行为变化

| 场景 | 原风险 | 当前行为 |
| --- | --- | --- |
| 两个请求处理同一文档 | 各自创建流水线与锁，可以交叉删除 / 创建切片 | 文档锁由共享数据层持有，跨流水线串行 |
| 重复点重新解析 | 同一文档重复排队、重复调用模型 | 入队之前预约文档，第二次请求返回 `SPACE_LOCKED` |
| 摄取期间开始重建 | 集合标记只挡新请求，已有写入继续进行 | 写入许可覆盖操作与排队生命周期，维护获取失败时不清空索引 |
| 同时重建两次 | 集合重复 add 不报错，一次 unlock 就解除了另一次保护 | 维护许可有唯一所有权，重复获取拒绝 |
| 维护中删除文档 | 原删除路径未检查维护锁 | 删除本身获取互斥许可，冲突时不更改资料 |
| 两次重复上传同一文件 | 共用原文路径，失败请求可能删除成功请求的文件 | 每个请求拥有独立文件，重复内容由唯一约束确认，只清理自己的副本 |
| 去重检查与插入之间发生竞态 | SQLite 唯一约束报错成为 500 | 返回 `DUPLICATE_DOCUMENT` 与已存在文档 ID |
| 处理任务被取消 | 状态仍停在解析 / 向量化，需要等重启发现 | 立即写入失败状态并通知进度订阅，可以重试 |
| 切片更新完成但向量化失败 | 元数据版本已更新，`only_stale` 不再选择它 | 失败 / 中断状态同样纳入增量恢复 |
| 切片创建失败 | 算法版本已提前被写入 | 只有创建切片成功才更新版本和词元数 |

## 实现边界

`OperationGate` 按空间共享。检查与获取之间不经过 `await`，维护许可显式传给本次流水线，使 SSE 生成器跨任务恢复、并发批次也能使用正确许可。普通请求不持有该许可。文档锁使用弱引用，不会因长期导入而永久积累每个文档的锁。

摄取登记、上传临时原文、排队预约、流水线处理、流式聊天及手动卡片抽取加入保护；文档删除、空间删除和导出在清理 / 写入退出后取得互斥许可。删除仍会先取消本空间已登记的后台任务和生成，新的并发写入会使维护请求拒绝，而不是关闭正在使用的数据库。

没有待重试文档时，无写入的空重试返回 `begin(total=0)` 与 `done(retried=0)`，避免其他正常摄取阻断空结果。

这是一套单进程操作协调，配合已有 SQLite / 向量库取消安全机制；不表示外部 Python 脚本或其他服务进程已经使用同一许可，也不等同于所有业务事务的跨文件原子提交。没有修改既有 SQL 迁移、用户资料或模型绑定。
